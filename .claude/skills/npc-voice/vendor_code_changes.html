Code changes

What has to change so a vendor says a different line each time a player walks up, and speaks it. Traced through the code on 23 Oct 2026; nothing here is built yet. Today one greeting goes NpcDefinition.greeting → NpcInteractable.Greeting → INpcDialogueSource (Core) → NpcInteractionUI.ShowDialogue, which prints it. No NPC plays a sound.

1. The data: more than one line, each with its sound

  • Gameplay/NPC/Runtime/NpcDefinition.cs: add a small NpcLine (the text and its AudioClip) and a NpcLine[] lines list. Keep greeting as the fallback when the list is empty, so every NPC asset keeps working before its lines arrive.
  • This is design data in a ScriptableObject, not a player save, so no save migration is needed.

2. Picking a line each visit

  • Gameplay/NPC/Runtime/NpcInteractable.cs: in Interact, pick one line before opening the dialogue, at random but never the same one twice in a row (remember the last one picked). Put the picker in a small pure function so a test can check it.
  • Each player's own game picks its own line. The dialogue only happens on that player's screen, so nothing goes over the network and the server is not involved.

3. Passing the sound to the window

  • Core/Runtime/INpcDialogueSink.cs: INpcDialogueSource.Greeting returns the picked line's text; add AudioClip GreetingClip for its sound. Core already uses Unity types (Vector3, Transform), so this keeps the layer rules: the NPC system implements it, the UI reads it, and neither calls the other directly.

4. Playing it

  • UI/Runtime/NpcInteractionUI.cs, ShowDialogue: show the picked text (it already does) and play its clip on one AudioSource of its own. Stop the clip when the dialogue closes or another NPC is opened, so two vendors never talk over each other.
  • Audio/Mixers/KN_Main.mixer: add a Voice group (it has Master, Music, Sfx, Ambience and UI today) with an exposed VoiceVolume, and send the dialogue's AudioSource to it.
  • UI/Runtime/Settings/AudioPreferences.cs: add Voice at the end of AudioChannel (after Interface, so the saved volumes keep their places), "voice" to Keys and "VoiceVolume" to Parameters.
  • Voices starts at 50 %, like every other sound (owner, 23 Oct 2026). Nothing extra is needed for that: Get already returns DefaultVolume (0.5) for a volume the player has never set, and Reset to defaults walks the same Keys. Leave VolumeDefaultsVersion alone: raising it would reset every player's other volumes too.
  • UI/Runtime/Settings/AudioSettingsTab.cs: add (AudioChannel.Voice, "Voices") to its Channels list. The VOLUME section builds one slider per entry, so the Voices slider appears under Interface and the player can turn it up or down like the others.

5. Getting the picks into the project

  • A new Editor tool, Gameplay/NPC/Editor/NpcVoiceImporter.cs (menu Krytical Nova ▸ NPC ▸ Import Voice Lines). It reads this page's picks, copies only the picked voice's kept lines from Drive into Assets/_Game/Audio/Voices/NPC/<Vendor>/ as compressed clips, and fills each NPC_*.asset's line list (text and clip). About 85 short clips, a few MB, committed once.
  • World/Editor/Zone01Setup.cs: NpcSeed.Greeting becomes a list of lines, and Refresh NPC Text From Seeds writes the texts, so a rebuild of Concord keeps them.

6. Checks

  • An EditMode test for the picker: it never repeats and reaches every line.
  • dependency_map.py --check and compile_check.py (game and server) before the commit; the server build gets no sound clips it can't use.
  • Play: walk up to a vendor several times and hear a different line each time, with the Voices slider working. Check it with a second client as well.
