# Player_01 Model Swap & Combo-2 Hit Fix

## Objective
Replace the Grruzam character model in `Assets/Prefabs/Player.prefab` with `Assets/Player_01/Player_01.prefab` while keeping locomotion, jump, katana draw/sheath and combat wiring intact, and make strike 2 of the katana combo register on the Combat Dummy like strikes 1 and 3.

## Changes
- 'Assets/Prefabs/Player.prefab' - (edit) swap the nested Grruzam model under `Visuals` for a nested `Player_01` instance, add an `AnimancerComponent` on the new model root, re-point socket / animancer references. This one prefab is BOTH the scene `Player` instance AND `NetworkManager.NetworkConfig.PlayerPrefab`, so a single edit covers the scene object and the runtime `Player(Clone)`.
- 'Assets/Scripts/Combat/WeaponHitbox.cs' - add per-combo-step collider reach support plus temporary diagnostic logging (swing step, collider enabled state, hitbox world center, distance to target, OnTriggerEnter rejections).
- 'Assets/Scripts/Combat/PlayerMeleeCombat.cs' - pass the current step's hitbox reach/window when opening a swing, log every accepted/rejected strike, and retune `swing2Start/swing2End` or `strike2Speed` only if the captured log shows the blade box never overlaps during the step-2 window.

## Relevant Assets and Quirks
- Working setup today: `Player/Visuals/CharacterModel` (child of `Visuals`, localPosition (0,-1,0)) is a nested instance of the Grruzam T-pose model; it carries an ADDED `AnimancerComponent` (fileID 7739874067338306076) wired to its own Humanoid `Animator` (avatar = `Modeling_T-Pose_Grrrru_Man(recommend).FBX`, Apply Root Motion OFF). `PlayerAnimancerMotor.animancer` and `PlayerMeleeCombat.animancer` both use that component. The separate `AnimancerComponent` on `Visuals` is vestigial (`Squash` is inactive) - leave it alone.
- Sockets are hand-added GameObjects on the model: `KatanaSheathSocket` under `.../spine_03` (localPos -0.12,0.14,0.22 / localRot quat -0.0797,0.8465,0.0635,0.5226) and `KatanaHandSocket` under `.../hand_r/ik_hand_gun` (identity). `KatanaBlade` (nested katana prefab + BoxCollider 0.18x0.18x1.15 trigger at z=0.55 along blade local +Z + Kinematic Rigidbody + `WeaponHitbox`) hangs off the sheath socket and is reparented at runtime by `PlayerAnimancerMotor` (`equipReparentNormalizedTime` 0.38).
- `Player_01` is the same rig family as the Grruzam model: same bone names (`root/pelvis/spine_01..03/clavicle_l,r/upperarm/lowerarm/hand/*_twist/ik_hand_gun/ik_hand_l,r/thigh/calf/foot/ball`), imported as Humanoid (animationType 3, own avatar), but **Apply Root Motion is ON** and it has NO `KatanaSheathSocket`/`KatanaHandSocket` (extra attach bones exist: `backAttach`, `hipAttachBack/l/r`, `prop_l/r`, `deprecated none`). Movement is NavMeshAgent-driven, so root motion must be OFF.
- The attack/equip clips key `ik_hand_gun`'s local transform directly, so blade pose in hand follows the clips, not the new rig's rest pose - mirroring the old socket transforms is a good starting point, final alignment needs a visual pass.
- `Combat Dummy` at (442,1,305.6), CapsuleCollider r0.5 h2 @ scale 0.8, no Rigidbody. `PlayerMeleeCombat`: prefab values `strike1Speed/strike2Speed/strike3Speed` = 1.3/1.3/1.0, `swing1` 0.22-0.65, `swing2` 0.22-0.65, `swing3` 0.20-0.70, `meleeStrikingRange` 2.2, `serverMaxValidationRange` 2.7. Scene instance only overrides strike1/strike3 speed (1.411 / 1.126).
- Clip lengths 1.267s / 1.167s / 2.433s at those speeds => the step-2 box is enabled for 0.197s-0.583s of a 0.897s strike, i.e. hardly different from step 1, so step-2 failure is more likely blade-vs-capsule geometry than the literal window value.
- `WeaponHitbox` only enables/disables a trigger collider, so all damage depends on `OnTriggerEnter` firing after a re-enable; nothing is currently logged, so step-2 behaviour has to be captured fresh (host mode via NetworkDebugHUD spawns `Player(Clone)` from this prefab).
