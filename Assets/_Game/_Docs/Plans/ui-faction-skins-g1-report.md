## 3. MegaBook and Feel

- **MegaBook 1.51** (`Assets/_ThirdParty/MegaBook`). A procedural 3D book: pages are meshes that bend and turn, each
  side takes a texture or a material, and objects can be attached to a page (`MegaBookPageAttach`). It knows nothing of
  UI. Four of its scripts carry an uncommitted local edit (a Unity 6 version check) that is needed for it to compile.
  To show a screen on a page there are two ways: (a) render the screen to a `RenderTexture` and give that to the page;
  (b) keep the live screen in front of the camera and use the book only as the stage and the transition.
- **Feel 6.1** (`Assets/_ThirdParty/Feel`), already used for all game feel (`GameFeelPresenter`, `MMF_Player`).
  Feedbacks that work with any UI because they act on the camera, post-processing, time or sound: camera shake and
  impulse, chromatic aberration, vignette, flash, time scale, sounds, haptics. Feedbacks that act on a `Transform`,
  `RectTransform`, `CanvasGroup`, `Image` or TextMesh Pro text (scale punch, position, rotation, wiggle, squash,
  fade, colour, text reveal) work on **uGUI directly**. A UI Toolkit `VisualElement` is not a component, so those need
  a small adapter of ours (a feedback that drives `style.scale`, `translate`, `opacity` and tint of a named element),
  or USS transitions for the simple cases (the HUD uses those today).

## 4. `KryticalTheme.uss`: the rules the skins follow

Sprites are white masks tinted with `-unity-background-image-tint-color`; 9-slice borders come from the sprite and are
scaled with `-unity-slice-scale`; a shared vocabulary (`.kn-panel`, `.kn-frame`, `.kn-title`, `.kn-eyebrow`,
`.kn-button-primary`, `.kn-toggle`, `.kn-card`, `.hud-movable`, `.blocks-world`); two fonts per skin (body, title);
gameplay colours are never skinned (the `.rarity-*` rules, level-gap name colours, faction namecard colours: the skin
builder leaves them alone). A sheet from the panel theme always loses to a sheet listed in a UXML document, so skin
sheets are `<Style>` entries of the document.

## 5. The Settings screen today

UI Toolkit (`Settings/SettingsWindow.uxml`), opened in game only (Esc menu, or its key). Four tabs:

| Tab | Options |
| --- | --- |
| Graphics | resolution, window mode, vertical sync, frame cap; quality preset, render scale, shadows, anti-aliasing, grass density, volumetric fog and mist, sun shafts, comic ink outlines |
| Audio | volume sliders per mixer group; mute while the game is in the background |
| Interface | HUD layout editor and reset, snap to grid; rings at the move destination and under the target; names over NPCs and players; my own namecard; screen shake and impact effects; Hotbar controls hint; pet chatter (new, workstream F); rotate the minimap; interface scale |
| Controls | key rebinding (click a key, press the new one; a key in use swaps), plus a list of fixed keys |

## 7. Recommended technical approach

1. **Keep the game in UI Toolkit and keep the title flow in uGUI.** Each already uses Synty's real art in the system
   it is built for, and no screen mixes the two. Moving the title flow to UI Toolkit would mean rebuilding five working
   screens to lose Synty's ready prefabs and Feel's direct feedbacks; moving the HUD to uGUI would mean rebuilding
   everything in section 1. The cost of the split is one thing: the shared Settings screen (point 4).
2. **One skin asset per faction** (`UiSkin`: frames, panels, buttons, bars, icons, fonts, accent colours, and for the
   menus the pack's prefabs for background, button, panel, crest). The HUD's skin sheets are then *generated from the
   asset* (the builder exists: it reads its sprite and font tables from the asset instead of from code), and the
   front-end builder builds each scene once per skin from the same asset. "Changing a value in a skin asset updates
   every screen" becomes: change the asset, the sheets and scenes are rebuilt.
3. **Menus per faction:** the front-end builder already instances Fantasy Menus prefabs by path. It gets the two other
   packs' matching prefabs from the skin asset and builds three variants of each scene's UI root; one is switched on at
   launch (random, kept for the run, or the Menu Theme setting).
4. **Settings in both places:** keep it UI Toolkit and show it over the uGUI character select in its own `UIDocument`
   (a whole screen of one system on top of another is not mixing inside a screen). It reads the same PlayerPrefs
   stores, so both entry points show and keep the same values. In game it wears the character's faction; from the menus
   it wears the menu skin.
5. **Feel:** on the menus, Feel's own feedbacks on the buttons and panels. In game, one adapter feedback of ours for
   `VisualElement`s plus the camera, sound and time feedbacks that already work. Inputs are never held back by an
   animation: feedbacks play beside the action, not before it.
6. **Screens that cannot reach the demo quality in UI Toolkit:** none found so far by reading. The risks are effects,
   not frames: animated shine and scrolling textures on buttons (uGUI materials in the packs), and the Dark Fantasy
   packs' own shaders. If one of those matters on a HUD element it would be drawn as a flipbook or left out; this is to
   be confirmed against the demo scenes before G-5.

## 8. MegaBook in the title flow (staging to approve)

The book is the stage; the screens stay live.

- A comic book lies open in the showroom scene, slightly tilted, lit by the showroom's key light. Its right-hand page
  is a blank panel of the faction's paper; the live uGUI screen is drawn over that page (screen-space camera canvas
  matched to the page's corners), so text stays sharp and every control works.
- Going forward (Title → Faction select → Creator → Select → Loading) the current screen is captured to a texture,
  put on the page, the live canvas is hidden for the length of the turn, the page turns (0.35 s, MegaBook), and the
  next screen is switched on over the new page. Going back turns the page the other way.
- Input is not blocked: a click during a turn finishes the turn at once. The Ben-Day wipe stays for scene loads.
- The cover (shown for a moment at launch) carries the game's logo in the faction skin of the run.
- Feel: a paper sound and a small camera push on each turn, a punch on the button that caused it.
